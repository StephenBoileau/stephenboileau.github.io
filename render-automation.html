01

Problem and constraints

NightFlight Expedition media needed high-resolution output at non-standard dimensions for attraction projection systems. Editors and clients needed VR-viewable reviews before the media was cut into the show. Multiple external vendors also contributed to production.

02

My ownership

Built the Unreal rendering pipeline and Python render automation. Owned environment optimization and deployed/administered the Linux/Google Cloud Perforce server for 4–5 external vendors and the internal team. Super 78’s broader production is team work; the making-of video is production context.

03

Implementation and key decisions

Python automation wraps Movie Render Queue to run nightly jobs. Raw output is converted to VR-viewable review media, renamed to project conventions, and filed in dated server folders. Slack alerts report completion and failure. Environment work includes LODs/HLODs, draw-call and texture/material reduction, lighting and shadow optimization, culling, streaming, and GPU/CPU/memory profiling.

04

Results and supporting evidence

Published throughput is 1–8 unattended renders a night. The workflow prepares headset review media for editorial and client review. The official making-of video identifies the production, but does not demonstrate the queue, error handling, or job logs.

05

Limitations and lessons

Job triggers, failure detection, retry/recovery logic, render times, and hardware are not described. NightFlight’s opening status conflicts within the current homepage, so no current attraction status is claimed here. A sanitized job log and render-to-review diagram would strengthen this case study.
